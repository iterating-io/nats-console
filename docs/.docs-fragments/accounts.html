계정과 사용자 관리

계정 생성, 권한, 자격 증명, 삭제 조건을 설명합니다.

계정 화면에서 기존 Operator 아래 계정을 만들고, 계정별 NATS 사용자를 관리합니다. Operator 신원은 서버에서 불러오며 콘솔에서 새 Operator를 만들지 않습니다. 계정을 만들 때 이름과 Operator를 지정하고 필요하면 publish/subscribe 허용 subject를 설정합니다.

생성 요청은 계정 키를 만들고 서명 키를 SQLite에 보관한 뒤, 기본 사용자 stream-reader를 생성합니다. 마지막으로 계정 JWT를 NATS full resolver에 보냅니다. 같은 Operator 안에서 중복된 계정 이름은 거부됩니다. 사용자 준비나 resolver 갱신이 실패하면 생성한 로컬 계정 데이터를 정리하고 오류를 반환합니다.

stream-reader 기본 권한
구분subject
publish 허용$JS.API.STREAM.INFO.*, $JS.API.STREAM.MSG.GET.*
publish 거부$JS.API.CONSUMER.>, $JS.API.STREAM.CREATE.>, $JS.API.STREAM.UPDATE.>, $JS.API.STREAM.DELETE.>, $JS.API.STREAM.PURGE.>, $JS.API.STREAM.MSG.DELETE.>
subscribe 허용_INBOX.>

일반 사용자는 계정에 속한 NATS 신원입니다. 콘솔에서 사용자를 생성하면 키와 권한 정보가 SQLite에 저장됩니다. creds 내보내기는 사용자 자격 증명을 외부 클라이언트에 전달할 때 사용합니다. 내보낸 파일은 접속 권한을 담으므로 접근 가능한 위치를 관리해야 합니다.

계정 삭제는 NATS resolver의 allow_delete가 켜져 있을 때만 가능합니다. 시스템 계정은 삭제할 수 없습니다. 삭제 요청은 관련 스트림과 source 연결을 먼저 정리하고, 검사 계정의 import를 해제한 뒤 resolver에서 계정을 삭제합니다. 정리 또는 resolver 삭제에 실패하면 API가 오류를 반환합니다.
